## 3. Analysis of 404 Not Found Route Patterns (34 Reported Errors)

Inspection of historical crawl logs, Netlify redirect tables, and React router declarations identified 4 distinct 404 clusters:

### Cluster 1: Bare City Slugs without Target Suffixes
- **Root Cause**: Early site versions linked to `/mesquite`, `/garland`, `/denton`, `/mckinney`, `/plano`, `/arlington`, `/irving`, `/frisco`, `/allen`, `/mansfield`, `/rowlett`, `/rockwall`, `/forney`, `/waxahachie`, `/weatherford`, `/burleson`.
- **Mechanism**: The edge function in Netlify redirects some in `canonicalMap`, but if direct requests hit static assets or unmapped edge paths, they fall through to 404.
- **Resolution**: Maintain permanent 301 redirects in `public/_redirects` at the top of the rule table before the SPA fallback (`/* /index.html 200`).

### Cluster 2: Legacy File Extensions (`.html`, `.php`, `.asp`)
- **Root Cause**: External backlinks or legacy site archives crawling `/index.html`, `/about.html`, `/contact.html`, `/products.html`, `/services.html`.
- **Resolution**: Implement 301 rewrites stripping `.html` and redirecting `/services.html` to `/solutions`.

### Cluster 3: Trailing Slash / Case Discrepancies
- **Root Cause**: Crawlers discovering uppercase links (e.g., `/Dallas`, `/Products`) or trailing slashes (`/pricing/`).
- **Resolution**: Netlify edge function `spa-404.ts` automatically normalizes pathnames via lowercase and trailing-slash removal prior to routing.

### Cluster 4: Removed/Renamed Product Model URLs
- **Root Cause**: Historical URLs for legacy equipment (e.g., `/zip-33i`, `/zip-35i`, `/zip-37g`, `/mx250-server`).
- **Resolution**: Map obsolete equipment URLs via 301 redirect to `/products` or the modern equivalent page (`/zip-43g`, `/zip-47g`, `/mx-series`).

## 4. Redirect Rules & Chain Prevention Analysis (`_redirects` & `netlify.toml`)

To ensure zero redirect chains, loops, or orphan redirects:

1. **Protocol & Host Consolidation**:
   - `http://` -> `https://`
   - `https://www.dallasfortworthzultys.com/*` -> `https://dallasfortworthzultys.com/:splat` (301)
2. **Canonical Mapping Redirection (Single Hop)**:
   - `/dallas` -> `/dallas-zultys-phones` (301)
   - `/fort-worth` -> `/fort-worth-zultys-systems` (301)
   - `/mesquite` -> `/mesquite-zultys-phone-systems` (301)

## 6. Canonical Strategy & URL Normalization Integrity

The application enforces strict canonical tagging via `src/utils/seoHelpers.ts`, `src/routes.ts`, and the build-time prerenderer:

- **Absolute Canonicals**: Every page injects `<link rel="canonical" href="https://dallasfortworthzultys.com/slug" />`.
- **Self-Referential Consistency**: Every canonical URL exactly matches the sitemap `<loc>` URL.
- **Alias Resolution**: In non-canonical alias pages, the canonical link targets the primary canonical route.
